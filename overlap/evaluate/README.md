# `evaluate/` — 평가

설정을 **감이 아니라 숫자로** 정한다. `config.Settings` 의 모든 기본값은
여기서 재서 나온 것이고, 바꿀 때도 여기서 다시 잰다.

## 파일

| 파일 | 무엇을 재나 |
|---|---|
| `indomain.py` | 공공 단위로 점수 방식 비교. `Top-1`, `Top-3`, `MRR`, `표본편향` |
| `cross.py` | **민간 질의로 재는 진짜 지표.** 방언이 다른 입력에서의 성능 |
| `coverage.py` | 분류별 표본이 쓸 만한가. 다음에 무엇을 더 받아야 하나 |

## 내부 평가만 믿으면 안 된다

`indomain` 은 질의도 직무기술서, 프로파일도 직무기술서다. 같은 방언끼리 맞춘 것이라
`일정계획준수` 라는 질의가 `일정계획준수` 항목에 문자열로 그대로 걸린다.
실제 사용자는 `학회 운영진 8명 일정 조율` 이라고 쓴다.

교차 평가를 넣자 **결론이 뒤집혔다.**

| 방식 | 내부 평가 | 교차 평가 Top-1 |
|---|---|---|
| L1 만 | 높아 보임 | 31.2% |
| L1+L2 | 이득 없어 보임 | **41.2%** |
| + 문장 투영 | — | **57.7%** (Top-3 77.2%) |

*(2026-09-16 기준. 직무 41개 · 민간 질의 369개)*

L2 가 해롭다고 썼다가 이 지표를 만들고 철회했다.
내부 평가를 버리는 게 아니다 — leave-one-out 이 붙은 정직한 지표이고,
`top_k` 나 `min_df` 처럼 **같은 방언 안에서 비교하면 되는 값**을 고르는 데 쓴다.

## 지표 읽는 법

- **Top-1** 1위로 맞힌 비율. `Top-3` 는 화면에 여러 개를 띄우는 실제 상황에 가깝다.
- **MRR** 정답 순위의 역수 평균. 1위=1.0, 2위=0.5. Top-1 은 2위와 50위를 구분 못 한다.
- **표본편향** `예측 1위 직무의 평균 단위 수 ÷ 질의 가중 평균 단위 수`.
  **1.0 근처가 좋다.** 분모를 단순 평균으로 잡으면 안 된다 —
  질의는 직무마다 단위 수만큼 나오므로 편향이 없어도 질의 가중 평균에 수렴한다.
  (지금 데이터에서 질의 가중 평균은 229) 이걸 한 번 잘못 읽고
  상위 150 을 300 보다 낫다고 판단한 적이 있다.
- **HHI** 기관 점유율의 제곱합. 유효단위가 못 잡는 '기관 수는 많은데 상위 몇 곳이
  절반 이상'인 경우를 잡는다.

## 교차 평가의 한계도 적어 둔다

정답을 **대분류 수준**으로만 잡는다(민간 자체 분류 → 허용 NCS 대분류 묶음).
소분류 단위 정답이 없기 때문이다. 그래서

- '정보통신 안에서 백엔드냐 보안이냐'는 못 잰다.
- 확장 노드의 기여도 안 잡힌다. 대부분 정보통신 안에서 갈리는 개념이라
  대분류 정답을 바꾸지 못한다.

KECO 연계표로 민간 직종명을 소분류에 잇는 게 다음 단계다.

## 절대 쓰지 않는 지표: 분류 간 겹침 비율

L2 를 넣으면 29.4% → 53.8% 로 오른다. 그런데 **같은 크기로 무작위 병합한
대조군이 61.1%** 였다(300회, z = −1.9). IDF 가중 Jaccard 로 바꿔도 같았다.
어휘를 줄이면 무엇으로 줄이든 겹침은 오른다. 이 숫자는 아무것도 증명하지 못한다.
대조군을 안 세웠으면 그럴듯한 거짓말을 발표할 뻔했다.

## 유효기간

여기서 나온 모든 숫자는 **그날의 데이터 기준**이다. 공고를 더 받으면 달라진다.
문서에 숫자를 적을 때는 기준일을 같이 적고, 갱신 때마다 다시 잰다.

## 다른 폴더와의 관계

- `recommend/matrix.py` 의 `effective_units()` / `hhi()` 를 **그대로** 쓴다.
  평가와 서비스가 다른 기준을 쓰면 평가가 의미를 잃는다.
- `competency/` 의 사전을 바꿔 끼우며 L1 / L1+L2 / 투영을 비교한다.
- `parse/requirements.py` 로 민간 질의를 만들고, `parse/roles.py` 의 직무 라벨을 정답으로 쓴다.
- `coverage.py` 의 결론은 `collect/` 의 다음 수집 계획이 된다.
- 실행은 `pipelines/evaluate.py`.
