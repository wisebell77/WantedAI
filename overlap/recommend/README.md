# `recommend/` — 대조 엔진

사용자 경험과 직무 공고를 맞춰 본다. **이 서비스의 출력이 나오는 곳이다.**

## 파일

| 파일 | 내용 |
|---|---|
| `matrix.py` | `JobMatrix`, `JobProfile` — NCS 소분류 × 역량 행렬 |
| `scorer.py` | `Recommender`, `JobMatch`, `GapReport`, `Evidence` — 정방향·역방향 |

## 정방향과 역방향은 같은 지표의 양 끝이다

```
정방향  목표 직무와 겹침이 부족한 곳      → 준비할 것    Recommender.forward()
역방향  안 본 직무와 겹침이 뜻밖에 많은 곳  → 새 선택지    Recommender.reverse()
                                                      Recommender.unexpected()
```

**역방향이 데모 하이라이트다.** 정방향은 "그래 나도 알아"지만 역방향은
"그건 생각 못 했는데"다. `unexpected()` 는 사용자가 이미 보고 있는 대분류를
통째로 빼고 답한다 — 정보통신을 보던 사람에게 정보통신 옆칸을 권하는 건 '뜻밖'이 아니다.

정방향도 비교 직무를 함께 낸다. "부족 12개"만 보여 주면 많은 건지 적은 건지 알 수 없다.

## 입도가 소분류인 이유

| 단계 | 개수 | 문제 |
|---|---|---|
| 대분류 | 24 | 너무 거칠다. 정보통신 하나에 백엔드·보안·AI 가 다 들어간다 |
| **소분류** | **279** | **개발·기획·운영이 갈린다. 표본도 버틴다** |
| 세분류 | 1,114 | 표본이 3~9건이라 통계가 안 된다 |

## 직무를 행렬에 넣는 기준 두 가지

```
유효단위 >= 30     기관당 8단위 상한을 건 뒤의 수
HHI      <  0.25   허핀달 지수 — 한 기관 쏠림
```

단위 수만 보면 속는다. `소성·소결세라믹제조`는 100단위로 상위권인데
기관이 2곳(한 곳 96%)이라 유효단위 12 로 떨어진다. 통계가 아니라 사례다.

## 역량을 상위 300개로 자르는 기준

`df × IDF` 순이다. 둘 중 하나만 쓰면 망가진다.

- `df` 만 → `문서작성`·`의사소통` 같은 범용어가 상위를 차지한다.
- `IDF` 만 → 딱 한 번 나온 파싱 오류가 1등이 된다(가장 희귀하므로).

곱해야 "이 직무가 실제로 요구하면서 고유한 것"이 남는다.
300과 500이 같은 성능이라 가벼운 쪽을 쓴다.

## 출력 규칙 — 어기면 서비스가 아니라 점집이 된다

1. **판정하지 않는다.** `JobMatch.sentence()` 가 화면 문구의 기준형이다.
2. **근거 없는 항목은 내보내지 않는다.** 모든 역량에 사용자 문장 + 공고 건수가 붙는다.
   `compare()` 가 근거를 못 찾은 역량을 조용히 버리는 게 그 구현이다.
3. **퍼센트를 쓰지 않는다.** 내부 점수(IDF 합)는 정렬 용도이고 화면에 띄우지 않는다.

## 다른 폴더와의 관계

- `competency/` 에서 사전과 투영기를 받는다. 역량 문자열을 직접 다루지 않는다.
- `taxonomy/` 에서 코드 ↔ 이름을 받는다.
- `evaluate/` 가 `JobMatrix.effective_units()` / `hhi()` 를 그대로 쓴다 —
  평가와 서비스가 같은 기준을 쓰지 않으면 평가가 의미를 잃는다.
- 행렬은 `pipelines/build_matrix.py` 로 만들어 `job_matrix.json` 에 저장한다.
  서비스는 그 파일만 읽으면 되고, 임베딩 모델은 **투영에만** 필요하다.
  (역량 목록을 이미 가진 호출자는 `JobMatrix.rank()` 만으로 모델 없이 돌릴 수 있다)
