# `competency/` — 역량 사전

**AI 가 실제로 일하는 곳이다.** CLAUDE.md 의 문장 그대로:

> AI 가 하는 일은 "서로 다르게 쓰인 말을 같은 역량으로 묶고, 요구 수준까지
> 읽어내는 것"이다. AI 를 빼면 남는 건 키워드 빈도표뿐이어야 한다.

## 3층 구조

| 층 | 파일 | 하는 일 | 예 |
|---|---|---|---|
| L1 | `normalize.py` | 표기만 맞춘다. 규칙 기반 | `컴퓨터 활용 능력` → `컴퓨터활용` |
| L2 | `cluster.py` | 의미로 묶는다. 임베딩 + 거리 | `보안패치및업그레이드` ≡ `서버보안소프트웨어설치및운영` |
| 투영 | `projector.py` | 자연어 문장을 노드에 붙인다 | `학회 운영진 8명 일정 조율` → `일정계획준수` |

여기에 축이 하나 더 있다.

| 파일 | 하는 일 |
|---|---|
| `extensions.py` | 민간 공고에서 **공공 축에 없는 역량**을 자동으로 뽑는다 |
| `dictionary.py` | 공공 축 + 확장 노드를 한 사전으로 합친다 |

## 왜 L1 만으로는 안 되는가

L1 만 돌리면 어휘가 3% 줄고 분류 간 겹침은 2.5% → 3.0% 에 그친다.
표기 흔들림은 이 데이터의 주된 문제가 아니다. 진짜 문제는 **의미가 같은데
글자가 하나도 안 겹치는 것**이고, 그건 규칙으로 못 잡는다.

## 왜 런타임에 LLM 을 안 부르는가

5만 종을 한 프롬프트에 넣을 수 없다. 쪼개 넣으면 묶음마다 군집 이름이 달라지고
매번 결과가 달라져 성능 비교가 무의미해진다. 요청마다 부르면 느리고 비싸다.

- 군집 자체는 **임베딩 + 거리 기준**으로 만든다. 결정적이고 재현된다.
- LLM 은 오프라인에서 '군집 이름 다듬기'와 '경계 사례 검토'에만 쓴다.

거리 임계는 지금 **0.38**이다. 느슨하게 묶어야 표현 차이를 넘는다
(0.15 는 Top-1 24.7% 로 L1 에 수렴한다).

**이 값은 어휘에 딸린 값이지 고정 상수가 아니다.** L1 의 괄호 처리를 고쳐
깨진 변형들이 합쳐지자 군집 대상이 8,965 → 12,644종으로 늘었고, 같은 0.35 가
훨씬 잘게 쪼개면서(군집 2,047 → 2,597개) 교차 평가 Top-1 이 61.1% → 56.7% 로
떨어졌다. 0.38 로 입도를 되돌리니(군집 2,045개) 59.8% / Top-3 79.1% 로
원래대로 돌아왔다. 떨어뜨린 건 정규화가 아니라 입도였다.

→ **어휘를 건드렸으면 이 값을 다시 잡는다.** `evaluate.py --clusters` 로 잰다.

## 왜 축이 둘인가

민간 공고 요건을 공공 축에 투영했더니 60% 만 붙었다.
안 붙는 40% 는 AI·클라우드·CAD/CAE·ERP 처럼 덩어리로 빠졌다.
NCS 개정 주기가 시장 속도를 못 따라가서 생기는 공백이다.

엔진을 두 개 만드는 게 아니다. **두 출처가 한 공간에 들어간다.**
확장 노드는 공공 노드 하위로 매달거나(`Spring` → `소프트웨어개발프레임워크`),
대응 개념이 없으면 새 축을 세운다(`NEW:클라우드인프라`).
자동 추출 기준 6가지(출처·빈도·분산·미충족·형태·드리프트)는 `extensions.py` 첫머리에 있다.
**상위 연결만 수동이다** — 자동으로 부모를 정하면 틀렸을 때 조용히 틀린다.

## 미매칭을 버리지 않는 이유

`ProjectionResult.unmatched` 는 사전에 못 붙인 문장이다. 억지로 붙이면
근거 문장은 나오지만 말이 안 되는 근거가 된다(CLAUDE.md 가 금지).
대신 모아 둔다 — 반복해서 쌓이는 표현이 다음 확장 노드 후보다.

## 남아 있는 문제 (숨기지 않는다)

- **`[벤치마킹]` 쓰레기 군집 609종.** 열어 보니 32% 가 불릿 문자를 달고 있다 —
  `￮노동법` `Ÿ품질관리체계심사` `⚫LMO시설및관리` `약품ž집기비품관리`.
  `normalize.LEAD_NUM` 이 잡는 불릿은 `○ ● ㅇ □ ■ ▪ · • -` 뿐이라, HWP 에서
  심볼 폰트로 찍힌 것들이 그대로 남는다. 알 수 없는 문자가 임베딩을 지배해
  의미가 전혀 다른 항목들이 한 덩어리가 된다. 괄호 문제와 같은 계열이다.
  나머지 68% 는 `약품`·`공정` 같은 평범한 짧은 단어라 불릿만 고쳐서는 안 없어진다.
- `[업무용소프트웨어활용]` — 소프트웨어아키텍처/공학/개발이 잘못 합쳐졌다.
- 거리를 0.50 까지 키우면 교차 평가 Top-3 는 80.6% 로 제일 높지만
  `[유지관리]` 770종 · `[벤치마킹]` 710종 두 덩어리가 어휘를 삼킨다
  (`마케팅전략 → 홍보`). **숫자만 보고 고르면 안 되는 이유다.**

## 다른 폴더와의 관계

- `parse/` 에서 `JobUnit.sections`(공공 어휘)와 `RequirementExtractor`(민간 문장)를 받는다.
- `recommend/` 가 `CompetencyDictionary.fold()` 로 역량을 접고,
  `TextProjector` 로 사용자 경험 문장을 노드로 바꾼다.
- `evaluate/` 가 사전을 바꿔 끼우며 L1 / L1+L2 / 투영의 기여분을 분리해 잰다.
- 임베딩 캐시(`l2_emb.npz`)를 `cluster.py` 가 만들고 `projector.py` 가 재사용한다.
  **npz 는 접근할 때마다 압축을 푼다.** 반복문 안에서 `z["E"]` 를 쓰면
  항목 수만큼 전체 배열을 다시 읽어 메모리가 터진다 — 한 번만 꺼내 쓴다.
