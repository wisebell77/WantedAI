# `collect/` — 공고 수집

**네트워크를 타는 코드는 전부 여기에만 있다.** 다른 폴더는 파일만 읽는다.
수집은 느리고(시간 단위), 한도가 있고(일 1만 회), 실패한다(서버 다운·IP 차단).
그 불안정을 이 폴더 안에 가둬 둬야 나머지를 마음껏 다시 돌릴 수 있다.

## 파일

| 파일 | 내용 |
|---|---|
| `base.py` | `Budget`(호출 예산), `QuotaExceeded`, `SourceDown`, `HttpClient`, 캐시 입출력 |
| `alio.py` | `AlioClient`(공시 목록·상세), `PublicCollector`(연도 수집), `NCS_MAJOR` |
| `attachments.py` | `AttachmentFetcher` — 첨부 다운로드 + PDF/HWP/HWPX/ZIP 텍스트화 |
| `private.py` | `GongchaeClient`(고용24 공채속보), `PrivateCorpus`(static·browser·ocr 병합) |
| `jobinfo.py` | `JobInfoClient` — NCS 분류에 **공식 설명**을 붙인다 (고용24 215L01) |

`jobinfo.py` 는 매처가 아니라 **사전**이다. API 매칭이 소박한 문자열 비교라
`데이터 분석` 을 넣으면 금융 신용등급 사후관리가 나온다. 그래서 이름으로 조회한 뒤
**코드가 일치하는 것만** 남긴다. 받은 문장은 공식 능력단위 정의 그대로 쓴다.

## 두 갈래

```
공공 (ALIO)                          민간 (고용24 공채속보)
목록 → 상세 → 첨부(직무기술서)        목록 → 외부 URL → 본문 3경로
= 학습·추천 모집단                    = 교차평가 질의 · 확장 노드 재료 · 실시간 공고
```

민간으로 직무 프로파일을 만들지 않는다. 건수가 모자라고 분류 라벨이 없다.
공공은 NCS 라벨이 붙은 직무기술서를 첨부로 공개하는 **유일한 합법 경로**다
(고용24 채용정보 API 는 개인회원에게 막혀 있고, 플랫폼 크롤링은 금지다).

## 다른 폴더와의 관계

- `parse/` 를 쓴다 — 첨부 텍스트화에 `HwpTextExtractor` 를 부른다.
- `config.PATHS` 가 정한 자리에 캐시를 쌓는다. 그 아래로는 아무도 간섭하지 않는다.
- `evaluate/coverage.py` 와 **같은 숫자**(`institution_cap`)를 쓴다.
  '무엇을 더 받아야 하나'와 '무엇을 신뢰할 수 있나'가 같은 기준이어야 하기 때문이다.
- 실행은 `pipelines/collect_public.py`, `pipelines/refresh_private.py`.

## 수집 순서가 데이터 품질을 만든다

단순히 많이 받는 게 아니다. `PublicCollector.interleave()` 가 하는 일이 핵심이다.

1. **분류별로 번갈아** — 순서대로 받으면 예산이 떨어질 때 뒤쪽(정보통신)이 통째로 빈다.
2. **기관별로 번갈아** — 한 기관을 연달아 받으면 그 기관이 분류를 대표해 버린다.
   재료 143단위 중 기관이 5곳(한 곳이 87%)이었던 게 그 결과다.
3. **이미 `max_per_inst` 단위를 가진 기관은 건너뛴다.**

## 실패를 다루는 방식

| 상황 | 처리 |
|---|---|
| 일일 한도 초과 | `QuotaExceeded` 로 즉시 중단. HTTP 429 + JSON 이라 파싱이 성공해 '데이터 없음'으로 오해하기 쉽다 |
| 파일 서버 다운 | 연속 5회 연결 실패 → `SourceDown`. 받은 것을 저장하고 끝낸다 |
| 첨부 하나가 깨짐 | 그 건만 건너뛴다. 예외 격리가 없어 500건을 날린 적이 있다 |
| 0바이트 캐시 | 읽다 실패하면 지우고 다시 받는다 (`read_json`) |
| IP 차단 | 첨부 간 1.5초 대기. 막히면 복구 대기가 훨씬 길다 |

중단돼도 캐시가 남으므로 **같은 명령을 다시 돌리면 이어서** 받는다.

## 알아 둘 것

- 파일 다운로드는 `www.alio.go.kr/download/download.json?fileNo=` 만 살아 있다.
  `opendata.alio.go.kr` 경로는 죽어 있다.
- API 서버(`apis.data.go.kr`)와 파일 서버(`www.alio.go.kr`)는 **별개**다.
  한쪽만 죽는 경우가 실제로 있었다.
- 공채속보는 `total` 이 340 안팎인 **스냅샷**이라 과거 조회가 안 된다.
  4일 만에 93건이 새로 올라오고 132건이 마감돼 사라졌다. 마감분도 우리는 계속 보관한다.
- 공채속보는 고용24 키를 쓰므로 공공데이터포털 일일 한도와 무관하다.
