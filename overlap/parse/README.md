# `parse/` — 문서 해석

바이트와 HTML 을 구조로 바꾼다. **네트워크를 타지 않고 순수 함수에 가깝다.**
그래서 규칙을 고치고 바로 다시 돌려볼 수 있다 — 이 폴더의 규칙은 거의 전부
"이렇게 안 했더니 이런 오류가 났다"의 기록이다.

## 파일

| 파일 | 내용 | 입력 → 출력 |
|---|---|---|
| `hwp.py` | `HwpTextExtractor` | PDF/HWP/HWPX/ZIP 바이트 → 텍스트 |
| `sections.py` | `SectionParser` | 직무기술서 텍스트 → `{필요지식: [...], 필요기술: [...]}` |
| `units.py` | `UnitSplitter`, `JobUnit` | 문서 텍스트 → 직무 단위 목록 |
| `requirements.py` | `RequirementExtractor` | 민간 공고 본문 → 요건 문장 |
| `roles.py` | `RoleSplitter`, `JobClassifier`, `Role` | 민간 공고 → 직무 단위 |

위 셋이 **공공**, 아래 둘이 **민간** 경로다. 문서 생김새가 전혀 다르다.
공공은 `■ 필요지식` 아래 항목이 붙는 정형 문서, 민간은 구조가 없는 웹 페이지다.
민간 쪽은 문장을 **거르는** 일이 전부고, 공공 쪽은 **자르는** 일이 전부다.

## 왜 공고가 아니라 '직무 단위'인가

단위의 86% 가 여러 직무를 묶은 공고에서 나온다. 공고 단위로 세면
같은 공고의 전산(대졸)과 청소원(학력무관)이 같은 조건을 갖게 된다.
민간도 같다 — 이미지형 공고는 평균 2.8개 직무를 담는다.
근거 문장을 직무 본문 안에서만 찾아야 다른 직무의 문장이 근거로 붙지 않는다.

## 규칙마다 붙은 사고 기록

- **표제 길이 상한 24자** → `■ 교육요건(학력, 전공)/관련자격/경력 등 우대사항`(25자)을
  못 알아봐서 조건 텍스트가 역량으로 새어 들어왔다. `■` 접두사도 함께 처리.
- **짧은 표제는 완전 일치만** — `기술원`(기관명)이 `기술` 표제로 잡혀
  기관 소개문이 통째로 필요기술이 됐다.
- **줄바꿈으로 잘린 구를 잇는다**(`join_wrapped`) — `대한 지식`(87건), `분석 능력`(94건)이
  독립 역량으로 집계됐다.
- **서러게이트 처리** — HWP 텍스트에 홀로 남은 서러게이트가 섞이면
  인코딩 단계에서 수집 전체가 죽는다.
- **민간 요건 문장 필터** — 신호어(경험·능력·역량…)와 잡음어(접수·약관·COPYRIGHT…)를
  동시에 본다. 이 필터 전에는 확장 노드 후보 상위에 `Rights` `Reserved` `OPIc` 이 올라왔다.

## 다른 폴더와의 관계

- `collect/` 가 `hwp.py` 를 부른다(첨부 텍스트화).
- `taxonomy/NcsResolver` 가 `units.UnitSplitter.taxonomy_region()` 이 잘라 준
  분류체계 표 구간을 받아 코드를 확정한다.
- `competency/` 가 `JobUnit.sections` 로 어휘를 만들고,
  `RequirementExtractor` 로 확장 노드 후보 문장을 받는다.
- `evaluate/cross.py` 가 `RequirementExtractor` 로 교차 평가 질의를 만든다.
- `roles.JOB_RULES` 의 라벨이 `evaluate/cross.GOLD` 의 키다. 한쪽을 고치면 다른 쪽도 본다.
