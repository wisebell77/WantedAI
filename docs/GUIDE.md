# 참고 가이드

## 먼저 알아둘 점

현재 AI 코치는 과거 테스트 데이터 폴더를 임시로 읽고 있습니다. 새 크롤러가 완성되면, 화면과 AI 코치가 같은 형식의 공고 정보를 받을 수 있게 연결하면 됩니다.

과거 테스트 데이터 폴더는 Git에 포함하지 않습니다. 새 수집 데이터도 원문·이용 조건을 검토한 뒤 데이터베이스나 팀 API로 제공하고, 원본 파일 자체를 저장소에 올리지 않는 방식을 권장합니다.

중요한 것은 공고 원문을 많이 모으는 것보다, 공고 하나를 다른 공고와 헷갈리지 않게 정리하는 것입니다.

## 공고 한 건에 필요한 정보

아래 형식으로 공고 상세 정보를 제공해 주세요. `postingId`는 화면에 보이는 제목이 아니라, 데이터 안에서 바뀌지 않는 고유값이어야 합니다.

```json
{
  "postingId": "work24-123456",
  "companyName": "회사명",
  "positionTitle": "데이터 분석가",
  "jobFamily": "데이터/AI",
  "responsibilities": ["주요 업무와 요구사항을 정리한 문장"],
  "requiredSkills": ["SQL", "Python"],
  "preferredSkills": ["A/B 테스트"],
  "deadline": "2026-10-15",
  "sourceUrl": "https://원문-주소",
  "sourceType": "고용24",
  "sourceUpdatedAt": "2026-09-16T09:00:00+09:00"
}
```

### 입력 규칙

- `postingId`: `사이트이름-원본공고번호`처럼 만든다. 제목이나 회사명만으로 만들면 중복될 수 있다.
- `jobFamily`: 팀에서 미리 정한 직무군 이름을 사용한다. 예: `데이터/AI`, `서비스기획`, `마케팅`.
- `responsibilities`: 원문 전체를 그대로 넣기보다, 주요 업무·필수 조건·우대 조건이 담긴 문장을 배열로 정리한다.
- `deadline`: 날짜를 알 수 있으면 `YYYY-MM-DD`, 알 수 없으면 `null`로 준다. 마감일이 여러 개면 지원 마감일 하나를 골라 준다.
- `sourceUrl`, `sourceType`, `sourceUpdatedAt`: 나중에 사용자가 원문을 확인하고, 오래된 공고를 가려내기 위해 필요하다.

## 화면과 연결할 API

최소한 아래 두 요청을 제공하면 됩니다.

```text
GET /api/v1/job-contexts
GET /api/v1/job-contexts/{postingId}
```

첫 번째 요청은 공고 선택 목록용입니다. 여기에는 공고 본문 전체를 넣지 않아도 됩니다.

```json
{
  "items": [
    {
      "postingId": "work24-123456",
      "companyName": "회사명",
      "positionTitle": "데이터 분석가",
      "jobFamily": "데이터/AI",
      "requiredSkills": ["SQL", "Python"],
      "deadline": "2026-10-15"
    }
  ],
  "families": ["데이터/AI", "서비스기획", "마케팅"]
}
```

두 번째 요청은 선택한 공고 하나의 상세 정보입니다. 위의 “공고 한 건에 필요한 정보” 형식을 그대로 반환하면 됩니다.

## 과거 자료와 실시간 자료를 함께 모을 때

두 데이터는 목적을 나누는 편이 좋습니다.

| 자료 | 주된 용도 | 꼭 남길 정보 |
| --- | --- | --- |
| 2021~2025 아카이브 | 직무별 요구사항 변화, 자주 등장하는 역량 찾기 | 게시일, 마감일, 회사, 직무, 원문 주소, 정제된 본문 |
| 실시간 민간 공고 | 사용자가 지금 지원할 수 있는 공고 제공 | 공고 ID, 현재 상태, 마감일, 마지막 확인 시각, 원문 주소 |

같은 공고가 여러 사이트에 있을 수 있으므로, 원문 주소·회사명·직무명·게시일·마감일을 비교해 중복을 표시해 주세요. 한 공고를 삭제하지 말고 대표 공고 하나와 원본 출처 목록을 연결하면 나중에 확인하기 쉽습니다.

## 권장 작업 순서

1. 사이트별 원본 공고를 저장한다.
2. 원본에서 회사명, 직무명, 업무, 필수·우대 조건, 마감일을 뽑는다.
3. 공통 형식으로 바꾸고 `postingId`를 붙인다.
4. 날짜, 원문 주소, 회사명 중 빠진 값이 있는지 확인한다.
5. 같은 공고를 묶고 마지막 확인 시각을 기록한다.
6. 목록 API와 상세 API가 위 형식으로 나오는지 확인한다.

## 현재 코드에서 참고할 위치

- `server/local-server.mjs`: 현재 테스트 데이터를 목록·상세 API로 바꾸는 임시 코드
- `dist/coach.js`: 사용자가 공고를 선택하고 AI에 `postingId`만 보내는 화면 코드
- `server/upstage-career-coach.js`: 선택 공고 한 건과 사용자 경험만 AI에 전달하는 코드

새 크롤러가 준비되면 `server/local-server.mjs`의 테스트 데이터 읽는 부분만 새 데이터베이스 또는 팀 API 호출로 교체하면 됩니다. 화면과 AI 요청 형식은 유지하는 것이 좋습니다.

## 주의할 점

- API 키, 로그인 정보, 쿠키는 코드나 Git에 올리지 않습니다.
- 사이트 이용 조건, 요청 횟수 제한, 공개 범위를 먼저 확인합니다.
- 원문 전체를 외부에 다시 공개해야 하는지와 보관 기간은 팀에서 정합니다.
- 과거 공고는 “현재 채용 중”으로 표시하지 않습니다. 실시간 공고에는 마지막 확인 시각과 마감 여부를 함께 둡니다.
