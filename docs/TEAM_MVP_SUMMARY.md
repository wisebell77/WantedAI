# Overlap MVP 공유 요약

## 서비스 목적

사용자가 선택한 채용공고와 본인 경험을 바탕으로, 지원 준비를 정리하고 면접 연습까지 도와주는 서비스입니다. 핵심은 **선택한 공고 한 건의 정보만 근거로 답하는 직무 AI 코치**입니다.

## 현재 구현된 기능

### AI 코치

- 선택 공고와 경험을 바탕으로 지원 준비 타임라인, 이번 주 할 일, 자소서 시작 방법, 직무 상담을 제공합니다.
- 공고마다 대화와 할 일을 분리해 두어 다른 공고의 정보가 섞이지 않게 했습니다.
- 빠르게 정리할 수 있는 타임라인·할 일 요청은 `solar-mini`, 설명과 평가가 중요한 자소서·상담·면접은 `solar-pro4`를 사용합니다.

### 화상면접

- 카메라와 마이크로 답변을 녹화하고 결과 화면에서 다시 볼 수 있습니다.
- 질문 공개 후 20초 준비 시간을 제공하며, 준비 시간 안에 시작하지 않으면 자동으로 녹화를 시작합니다.
- faster-whisper medium 모델(beam size 5)로 답변을 전사합니다. 선택 공고의 회사·직무·기술 용어를 전사 힌트로 함께 사용합니다.
- 말하기 속도, 긴 침묵, 습관어와 영상 랜드마크 기반 신호를 확인합니다.
- MediaPipe 얼굴·손·제스처·자세 분석 결과를 녹화 영상 위 오버레이와 결과 화면에서 볼 수 있습니다.
- 면접 답변 내용은 Upstage API가 선택 공고의 JD와 답변을 근거로 평가하고, 후속 질문을 만듭니다.

## AI가 답하는 방식

직무별로 별도의 모델을 새로 학습한 방식은 아닙니다. 요청이 들어올 때마다 서버가 `postingId`로 선택 공고를 다시 찾고, 그 JD와 사용자 입력만 Upstage에 전달합니다.

따라서 AI는 공고에 없는 요구사항이나 사용자가 말하지 않은 경험을 사실처럼 만들지 않도록 제한되어 있습니다. 면접에서는 답변·질문·말하기 지표를 함께 전달하지만, 말하기 지표는 연습용 참고 자료일 뿐 채용 합격 여부를 판단하는 데 쓰지 않습니다.

## 주요 API

| API | 하는 일 |
| --- | --- |
| `GET /api/v1/job-contexts/{postingId}` | 선택 공고의 JD 정보 반환 |
| `POST /api/v1/agent/chat` | 타임라인, 할 일, 자소서, 직무 상담 요청 |
| `POST /api/v1/agent/interview-feedback` | JD 기반 면접 답변 평가와 후속 질문 생성 |
| `POST /api/v1/interview/transcribe?postingId=...` | 녹화 음성을 텍스트로 전사 |

면접 평가 API에는 `postingId`, 면접 질문, 전사된 답변, 전달 지표를 보냅니다. 서버는 브라우저가 보낸 JD나 루브릭을 믿지 않고, `postingId`에 해당하는 공고 정보를 직접 사용합니다.

## 실행 방법

```bash
cp .env.example .env
# .env에 UPSTAGE_API_KEY 입력
npm run dev
```

- AI 코치: `http://127.0.0.1:4173`
- 화상면접: `http://127.0.0.1:4173/index.html?postingId=role-1`

`UPSTAGE_API_KEY`는 `.env`에만 보관하며 Git에 올리지 않습니다.

## 팀 연동 시 참고할 점

- 현재 로컬 서버는 테스트용 크롤링 파일에서 공고 정보를 읽습니다. 크롤링 팀 API가 준비되면 `postingId`를 유지한 채 공고 조회 부분을 그 API로 바꾸면 됩니다.
- 공고 데이터에는 회사명, 직무명, 업무 내용, 필수·우대 역량, 마감일, 원문 주소가 있으면 됩니다.
- 지금의 직무별 질문과 일부 규칙 기반 전달 평가는 MVP용입니다. 실제 면접 기준으로 고도화하려면 현직자·채용 담당자 검토와 평가 데이터가 필요합니다.
- 사용자 대화와 할 일은 현재 브라우저에만 저장됩니다. 여러 기기에서 이어서 사용하려면 로그인과 데이터베이스가 추가로 필요합니다.
