# Overlap — 직무 추천 엔진

**당신의 경험 위에, 채용 공고를 입히다.**
채용공고 역파싱 기반 역량 격차 · 인접 직무 매칭 엔진 — 원티드 AI Championship 2026.

이 저장소는 팀 프로젝트 중 **직무 추천 파트**다.
경험 원문(프로젝트·인턴·활동)을 받아 실제 채용공고가 요구하는 역량과 대조한다.

```
입력   "학회 운영진으로 8명 일정 조율"  "설문 300건 정리해 보고서 작성"
          ↓ 문장을 역량 노드에 투영
출력   인사·조직 공고가 요구하는 역량 중 4개가 당신의 경험과 겹칩니다 (공고 41건 · 기관 29곳)
         회의운영                                        공고 8건에서 요구
           당신의 경험 — 학회 운영진으로 8명 일정 조율
           공고 원문   — 회의 운영 및 진행 기술
                         한국OO공단 2024년 신입직원 채용 [원문 보기]
```

## 무엇이 다른가

LinkedIn Career Explorer 도 역방향 매칭을 한다. 다른 건 **입력**이다.
Career Explorer 는 *현재 직무 타이틀*을 요구한다. 우리 타깃인 취준생에게는 그게 없다.
우리는 **경험 원문**을 받고, 모집단이 **실제 한국 채용공고 본문**이다.

## 지키는 규칙 네 가지

1. **판정하지 않는다.** "당신은 HR 이 맞습니다"(X) / "HR 공고가 요구하는 역량 7개와
   겹칩니다, 마케팅은 3개"(O). 대조만 하고 해석은 사용자가 한다.
2. **근거 없는 출력은 없다.** 역량 하나에 **양쪽 근거**가 붙는다 — 사용자 경험 원문,
   그리고 그 직무 공고에 실제로 적혀 있던 표기 + 기관·공고명·원문 링크.
   한쪽이라도 못 대면 그 항목을 뺀다. **부족한 역량도 예외가 아니다** —
   그것도 "이 직무가 이걸 요구한다"는 주장이기 때문이다.
   민간 공고는 본문을 인용하지 않고 "어느 기업의 어떤 직무가 요구하는지"까지만 낸다.
   일반적인 학습 조언은 넣지 않는다.
3. **퍼센트를 쓰지 않는다.** 아래 '무엇을 재지 않는가' 참고.
4. **채용 플랫폼을 크롤링하지 않는다.** 공개 API 와 기업 자체 채용 페이지만 쓴다.

## 구조

```
overlap/        엔진 (라이브러리)
  config.py       경로·상수·인증키. 모든 모듈이 여기만 본다
  collect/        공고 수집 — 네트워크를 타는 코드는 전부 여기에만
  parse/          바이트·HTML → 구조
  taxonomy/       NCS 분류 확정
  competency/     역량 사전 (L1 표기 → L2 의미 → 문장 투영, + 확장 노드)
  recommend/      직무 × 역량 대조. 정방향·역방향
  evaluate/       설정을 숫자로 고른다
pipelines/      실행 스크립트 (얇은 껍데기. 로직은 두지 않는다)
```

폴더마다 README 가 있다. **각 폴더가 무엇을 맡고 어디와 맞물리는지**는 거기에 적혀 있다.

## 시작하기

```bash
pip install -r requirements.txt
cp .env.example .env        # DATA_GO_KR_KEY, WORK24_KEY_RECRUIT 를 채운다
```

```python
from overlap import Recommender

r = Recommender()
for m in r.reverse(["학회 운영진으로 8명 일정 조율", "설문 300건 정리해 보고서 작성"]):
    print(m.sentence())
```

바로 돌려 보려면:

```bash
python pipelines/recommend_demo.py --preset 데이터분석
```

## 데이터 파이프라인

```
collect_public.py  →  build_units.py  →  build_dictionary.py  →  build_matrix.py
  ALIO 공고·첨부        직무 단위 + NCS      L2 군집 + 확장 노드      행렬 + 근거 인덱스
  [느림·한도·실패]        [캐시만 읽음]         [임베딩. 캐시 있음]       [빠름]

refresh_private.py →  민간 공고 → 직무 단위 (교차평가 질의 · 확장 노드 재료 · 실시간 공고)
evaluate.py        →  커버리지 / 내부 평가 / 교차 평가
```

수집만 네트워크를 탄다. 나머지는 캐시만 읽으므로 규칙을 고칠 때마다 다시 돌리면 된다.
**데이터를 갱신했으면 build_units → build_dictionary → build_matrix → evaluate 를
순서대로 다시 돌린다.** 하나만 돌리면 앞뒤가 안 맞는다.

## 서비스가 읽는 것은 5MB뿐

원본 데이터(HWP·PDF 694MB)는 **빌드에만 쓰인다.** 서비스는 산출물만 읽는다.

| 파일 | 크기 | 내용 |
|---|---|---|
| `job_matrix.json` | 1.0 MB | 직무 38개 × 역량 10,361개 (요구 건수 + IDF) |
| `evidence.json` | 1.9 MB | 공고 원문 표기 + 출처 문서 1,043건 (gzip 0.4MB) |
| 노드 벡터 | 3.0 MB | 2,051개 × 768차원 float16 |
| 사전·분류표 | 1.8 MB | L2 군집, 확장 노드, NCS 분류표 |

`evidence.json` 은 직무 단위로 쪼개면 gzip 49KB 라 사용자가 펼칠 때만 불러오면 된다.
과거 공고를 데이터베이스에 넣을 이유가 없다 — 행렬을 만들 때 한 번 쓰이고 끝이다.

## 왜 공공기관 공고가 모집단인가

민간 공고 본문을 주는 공개 API 가 사실상 없다. 고용24 채용정보 API 는 개인회원에게
막혀 있고(직업정보제공사업 신고확인증이 필요하다), 플랫폼 크롤링은 금지다.
ALIO 는 NCS 기반 직무기술서를 첨부로 공개한다 — 분류 라벨이 붙은 한국어 직무 문서를
수천 건 모을 수 있는 유일한 합법 경로다.

민간은 **실시간 공고**와 **축의 공백을 메우는 역할**을 맡는다. 이건 콜드 스타트로 다룬다.
데이터가 쌓이거나 사업자 자격으로 고용24 권한을 얻으면 한 번에 채울 수 있다.

## 무엇을 재는가

| 지표 | 무엇 | 왜 |
|---|---|---|
| 교차 평가 Top-1/Top-3 | 민간 공고 요건 문장으로 NCS 분류를 맞히는가 | **방언이 다른 입력**에서의 성능. 실제 사용 상황에 가장 가깝다 |
| 내부 평가 Top-1/MRR | 공공 단위를 leave-one-out 으로 | `top_k`·`min_df` 처럼 같은 방언 안에서 고르면 되는 값 |
| 표본편향 | 예측이 표본 큰 직무로 쏠리는가 | 1.0 근처가 공정. 분모는 **질의 가중** 평균이다 |
| 유효단위 · HHI | 이 분류를 통계로 믿어도 되는가 | 단위 수만 보면 한 기관의 채용 관행을 '직무 요구'로 착각한다 |

## 무엇을 재지 않는가 — 분류 간 겹침 비율

L2 군집을 넣으면 분류 간 겹침이 29.4% → 53.8% 로 오른다.
그런데 **같은 크기로 무작위 병합한 대조군이 61.1%** 였다(300회, z = −1.9).
IDF 가중 Jaccard 로 바꿔도 같았다. 어휘를 줄이면 무엇으로 줄이든 겹침은 오른다.

이 숫자는 아무것도 증명하지 못한다. 근거로도, 사용자 출력으로도 쓰지 않는다.
대조군을 안 세웠으면 그럴듯한 거짓말을 발표할 뻔했다.

## 한계 (숨기지 않는다)

- 교차 평가 정답이 **대분류 수준**이다. 소분류 안의 구분과 확장 노드의 기여는 못 잰다.
- L2 군집에 실제 오류가 있다. `[벤치마킹]` 609종은 32% 가 불릿 문자 잔해
  (`￮노동법` `⚫LMO시설및관리`)이고, 나머지는 `약품`·`공정` 같은 짧은 일반명사다.
  `소프트웨어아키텍처`가 `업무용소프트웨어활용`에 잘못 붙는 문제도 남아 있다.
- 확장 노드가 44개(고유 노드 37개)다.
- 모든 수치는 **그날의 데이터 기준**이다. 공고를 더 받으면 달라진다.
  문서에 적을 때는 기준일을 같이 적는다.
